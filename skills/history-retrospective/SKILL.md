# Learn from actual work

## Establish the evidence

Read the current instructions, relevant skills and previous accepted or rejected
retrospective decisions. Use [agent-history](../agent-history/SKILL.md) for archive
retrieval and historical evidence handling.

For a broad review, start with the newest conversations, then widen across dates,
projects and available devices. Use older work to corroborate patterns and test
the initial hypothesis. Search both recurring task types and costly detours.
Metadata inventories establish coverage, not how many conversations were read.

Include scenarios or guidance seen in at least two independent instances, even
without a complaint, and incidents that wasted time or effort. A costly single
incident is a candidate; it does not by itself establish a global rule.
Retrieve the original dialogue needed to support each candidate. Missing user
acceptance, outcomes or instruction-version evidence limits what can be claimed;
state the gap rather than automatically excluding the candidate. Distinguish
observed cost, estimated cost and an accepted tradeoff.

## Find what would change the next attempt

Keep already-covered patterns in the findings. Separate missing guidance from
poor execution, skill activation problems, and rules that have since been fixed.
Before declaring a gap, follow relevant references in the existing guidance
and check their coverage of the candidate.
Separate current coverage, actual loading and observed behavior. When loading
evidence would change the disposition, check archived calls or injected
instructions. For claims about an instruction's effect, verify the version
actually loaded where possible; today's file does not describe an older live
session. Loading alone does not establish compliance or improvement.
Look for later revisions and counterexamples before generalizing a preference.

Describe the recurring decision or reusable workflow and what, if anything,
should change next time. For changes, choose the smallest useful home:

- A short cross-task preference or decision principle belongs in AGENTS.md.
- A recurring workflow with recognizable triggers and useful judgment belongs
  in a skill. Reuse relevant existing skills before adding another.
- Project contracts, runbooks, paths and artifact conventions belong with their
  project. Do not turn historical machine state into global instructions.
- Unwanted automatic behavior may call for changing activation or removing a
  requirement, rather than adding another rule that fights it.

## Deliver and improve within scope

Order candidates by their most recent independent occurrence, newest first.
Lower the priority of patterns supported only by older work; an old high count
does not make a pattern current. Use the underlying interaction's date, not the
session's update time or a later retrospective quoting it. Within comparable
recency, weigh repetition, cost and remaining gaps in the current guidance.

Present independent examples, repetition or cost, current coverage and a
recommended disposition: retain, add, revise, remove or change activation.
State sampling limits and retrieval gaps.

Follow the current request's authorization: deliver recommendations and reviewable
text for a review, or implement authorized changes under the destination's rules.
For substantive skill changes, choose a representative task or real artifact to
check triggering and decisions. Format checks and prose review do not establish
improved behavior; additional review rounds need a concrete expected benefit.
Create persistent reports, update memory or schedule future reviews only when
requested.
